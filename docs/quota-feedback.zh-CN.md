# 配额反馈与汇总

端点套餐用量响应会提供可选的逐 Key `quota_status` 元数据，作用范围为 `text_inference`，状态包括 `available`、`exhausted`、`unknown` 和 `cooling`。详情视图仍保留原始 provider 窗口、余额、模型行及观测历史。

## 状态说明

- `available` 需要来自新鲜成功观测的默认文本可用额度。
- `exhausted` 表示适用的额度或余额约束已确认耗尽。重置时间已过的 0 不会被视为当前耗尽。
- `unknown` 表示额度信号缺失或不受支持、观测过期、刷新失败，或 0 值的重置时间已过。未知既不是 0，也不能证明额度可用。
- `cooling` 表示 Key 或端点正受有效冷却期影响。响应会在可用时提供冷却截止时间；截止后可进入受控恢复探测。

这些状态描述默认文本推理，而非所有模型或模态。MiniMax 汇总仅使用 `general` 模型行；视频等独立模型窗口仍会显示，但不会增加文本汇总。余额类 provider 保留原生单位，不合并不同币种；DeepSeek 可用性以 provider 的 `is_available` 标志为准。

## 有效徽标与详情

端点徽标会对短期和长期窗口使用相同的、已确认可用 Key 集合计算平均值。已确认耗尽或正在冷却的 Key 不会抬高汇总。所有适用 Key 均确认耗尽时，对应汇总为 0；只有部分 Key 已知时会标记为部分可用。新鲜度或适用性未知时，徽标会如实显示未知，而不会把缺失信号表示成可用或 0。

详情视图保留所有上报的 Key、模型、窗口、余额、重置时间和历史行。逐 Key 状态徽标是附加信息，不会替换或改写 provider 数值。提示信息中可查看观测时间、刷新失败和冷却截止时间。

## 刷新与范围

配额刷新会保留最近一次成功的原始观测，同时将刷新失败或过期观测标记为未知。后续成功刷新会恢复当前状态。OpenAI ChatGPT 订阅状态使用持久化观测时间和新鲜度规则，详见[配额快照](quota-snapshots.zh-CN.md)。

同一 Worker 进程中克隆的状态共享配额冷却反馈和套餐缓存。不同 Worker 不会即时共享冷却或反馈记录，因此各自观测和刷新收敛前可能显示不同状态。仅序列化配额元数据不会触发 provider 请求。
