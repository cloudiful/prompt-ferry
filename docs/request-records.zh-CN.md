# 请求记录

管理控制台会列出已记录的请求，并在概览中汇总这些请求。AI 分类与 MCP 分类是彼此独立的数据集，MCP 数据集还会按一个「范围」拆分，用于决定一次查询覆盖哪些 MCP 记录。

## MCP 范围

范围按记录身份拆分 MCP 记录，绝不依据请求路径或展示名称：

- `service` 保留真正发往 MCP 服务的记录。只要记录带有 MCP 服务端 id 或已保存的服务端名称，就属于服务侧，因此只有名称的失败尝试、以及已删除服务端遗留的历史 id 记录都仍留在服务侧。
- `gateway` 保留网关侧记录：既没有服务端 id、也没有服务端名称的记录。
- `all` 同时保留两者。

范围只作用于 MCP 分类；AI 记录、它们的计数、筛选项与概览都不会因此改变。控制台在进入或重置 MCP 分类时选择 `service` 范围；范围属于查询级状态，与行筛选器相互独立，重置行筛选器不会改变范围。切换范围会重置分页，并清除与新范围不兼容的筛选条件，避免服务端筛选条件遮蔽网关记录。选定的范围在记录、计数、筛选项、概览指标、趋势与分布中保持一致，概览缓存也按范围分别保存。范围选择器在记录视图与概览视图中都可用，且两者作用于同一个选择。

概览响应会带上服务端选定的趋势粒度（`hour` 或 `day`），客户端据此标注分桶，无需重复推导服务端的时间窗口逻辑。按天的分桶是逻辑上的 UTC 日历日期，不会因数据库会话时区而落到别的日期。

## 显示时区

管理控制台以「显示时区」渲染所有时间戳。该偏好位于通用设置中，与语言、主题一样保存在浏览器本地：`自动` 跟随浏览器报告的时区，手动 IANA 时区则覆盖它。`UTC` 与 `Asia/Shanghai` 始终可选；当运行环境能够枚举时区列表时，还可以搜索全部时区。

该偏好只改变展示的标签：它不会改变时刻本身，不会改变服务端保存的内容，也不会改变统计周期或日期范围——统计上的「天」分桶始终是逻辑上的 UTC 日历日期，「小时」分桶则跟随所选时区。偏好保存在浏览器本地存储中；当浏览器禁用本地存储时，当前会话内的选择依然生效，但重新加载后不会被记住。

记录行的日期与时间始终描述所选时区中的同一天，并且都会立即跟随该偏好，无需重新拉取记录。概览趋势使用服务端选定的粒度：天分桶标注其逻辑上的 UTC 日历日期，小时分桶则是所选时区中的时刻。

## API

记录、筛选项与概览接口都接受可选的 `mcp_scope` 参数，取值为 `service`、`gateway`、`all`：

```text
GET /api/v1/admin/request-records?request_category=mcp&mcp_scope=service
GET /api/v1/admin/request-records/facets?request_category=mcp&mcp_scope=service
GET /api/v1/admin/request-records/overview?request_category=mcp&mcp_scope=service
```

省略 `mcp_scope` 等同于 `all`，保持 MCP 查询的历史行为；非法取值会被拒绝。该参数是新增的，既有客户端无需改动即可继续使用。

MCP 分布表可直接打开它所描述的记录。每个分布行都带有其记录所属的范围，因此下钻不会依据展示名称或缺失的服务端 id 去猜测：网关记录行打开网关范围，带有服务端 id 的服务记录行打开该服务端，只有名称的服务记录行则打开服务范围并按其已保存的服务端名称过滤。
