# ChatGPT 额度快照

管理控制台会为 OpenAI ChatGPT 订阅额度保留成功观测的有界历史。额度对话框显示实际观测时间，并区分缓存、过期、刷新中以及刷新失败后继续显示的最近一次成功数据。刷新失败不会覆盖最近一次成功观测。逐 Key 默认文本状态会将过期、刷新失败或重置时间已过的观测标记为未知，同时保留原始窗口和历史记录。状态与汇总说明见[配额反馈](quota-feedback.zh-CN.md)。

## 前置条件与采集

- 持久化额度快照和历史需要 PostgreSQL Worker 后端。SQLite 独立模式仍可直接查看当前额度，但不提供持久化历史或自主周期采集。
- 周期采集通过 Valkey 协调。Valkey 协调不可用时会禁用周期采集；手动刷新和已选端点请求触发的唤醒仍可使用。
- 若前 30 分钟内记录到实际请求，活跃端点按 5 分钟周期刷新；空闲端点按 1 小时周期刷新。已选 OpenAI 订阅端点的请求可在观测超过 5 分钟时非阻塞地唤醒刷新。
- 没有历史观测的端点首次打开时最多触发一次获取。历史面板仅在展开时加载，每页最多 200 条。
- 成功观测保留 30 天。API 查询时会应用保留窗口，周期清理以有界批次删除过期记录。

迁移由应用部署的标准 `db_init` 初始化流程在 Worker 启动前执行。请使用经过授权的部署数据库迁移流程。

## 历史 API

管理员可按端点分页读取历史：

```text
GET /api/v1/admin/endpoints/{endpoint_id}/quota-history?limit=50
```

`limit` 默认 50，范围为 1 到 200。使用响应 `next_cursor` 中的不透明十进制 `before_id` 继续读取；快照 ID 以字符串传递，避免 JavaScript 64 位精度丢失。响应包含观测时间、计划类型、可选上游限额标记、归一化窗口、来源（`manual`、`request` 或 `periodic`）、下一页游标和保留天数。

历史按端点隔离，禁用的 OpenAI 端点仍可读取。历史只包含成功的归一化额度窗口，不包含访问令牌、账户标识、原始上游载荷、API Key 或原始错误文本。历史读取不会访问额度上游。PostgreSQL 存储故障返回通用服务错误，不会返回部分数据或伪造额度记录。

## 通用逐 Key 额度历史

所有具备采集能力的渠道（MiniMax、CommandCode、OpencodeGo、OpenRouter、GLM、DeepSeek，以及镜像的 ChatGPT 订阅结果）会为每次实际获取（手动、请求触发或周期采样）按 API Key 记录一行观测。缓存命中不会追加记录。额度对话框为除 generic 外的所有渠道挂载独立的逐 Key 历史面板，原 OpenAI 历史面板保持不变。历史行按各自观测时间渲染，即使窗口按当前时间已过期，显示的仍是当时观测值，而非当前额度断言。失败的获取以诚实的失败行呈现，携带稳定的错误码，不伪造百分比。

管理员可按端点读取，可选按单个 Key 过滤：

```text
GET /api/v1/admin/endpoints/{endpoint_id}/quota-observations?key_id=&limit=50
```

`limit` 默认 50，范围为 1 到 200；使用响应 `next_cursor` 中的不透明十进制 `before_id` 继续读取。不带 `key_id` 时，端点级查询返回全部历史 Key（包括已从配置中删除的 Key），按最新优先排序；带 `key_id` 时，仅返回该 Key 在本端点下的记录。历史保留 30 天，每小时以有界批次清理。活跃端点每 5 分钟采样，空闲端点每 30 分钟采样，周期采样依赖 Valkey 协调；Valkey 不可用时禁用周期采样，手动与请求触发的采集不受影响。

历史不支持回填：没有获取器的渠道（generic）永远不会产生记录，历史从采样开始时起算。该表由部署 `db_init` 迁移流程创建；生产库仅通过操作员授权的迁移获得空表。记录仅携带 Key 标签、渠道代码、计划元数据和 canonical 窗口，绝不包含 API Key、令牌或原始上游报文。

## 额度趋势图

展开的逐 Key 历史默认显示趋势图；可见的视图切换可返回同一个数据库游标分页列表。趋势图不会下载全部列表页：它按所选 Key 与时间范围读取一组有界、由服务端分桶的序列，而列表在模式切换间保留自己的 `before_id` 游标和已加载行。

管理员可为单个端点请求一个固定范围：

```text
GET /api/v1/admin/endpoints/{endpoint_id}/quota-observations/trend?key_id=&range=24h
```

`range` 取值 `24h`、`7d` 或 `30d`（默认 `24h`），其他值返回 `400`。服务端只快照一次 `now`，推导 `from = to - duration`，并将每条采样放入固定的半开区间 `[from, to)` 桶（`24h` = 900 秒/96 桶，`7d` = 7200 秒/84 桶，`30d` = 28800 秒/90 桶）。桶时间戳为 `from + index * step`，不会越过 `to`；`from` 与 `to` 均为 UTC 时间。

响应包含 `bucket_seconds`、`bucket_count`、`keys_truncated`、`series_truncated`、`sampled_observations`、`failed_observations` 和 `series`。每个序列是一个身份 `(key_id, source_id, kind, unit, metric)`，其 `points` 为固定长度且升序；没有可用观测、失败快照或所选行缺少该窗口的桶为 `null`，绝不沿用或伪造数值。余额使用原生单位的 `amount` 指标（真实的 0 与负值都保留）；已知百分比窗口使用 `0..100` 的 `remaining_percent`；无限制窗口没有数值序列。最多返回 24 个 Key 与 96 个序列，超限时给出截断标记而非静默丢弃。

趋势图按 `(metric, unit)` 分组，因此 CNY、USD、credits 与百分比各自独占坐标轴，绝不合并、填充面积或跨缺口插值；空桶保持为缺口，阶梯线承载观测到的水平而非暗示斜率。图例与提示名称组合 Key 标签与窗口槽位，两个 Key 标签相同时追加短 Key ID。头部显示范围、桶大小、采样与失败快照数量以及 Key/序列截断。全为 null 或没有序列时显示明确的空状态，而不是伪造的零线。这是余额与剩余额度历史，不是消耗或支出：趋势图不求和、不取差、不做换算，也不让不同货币共享坐标轴。

## 如何理解观测

已知的 0% 剩余与未知用量保持区分。窗口标签使用上游报告的实际时长，不会推断默认五小时或周窗口。观测时间是成功上游响应到达的时间，不是打开对话框的时间。后续刷新失败时，界面保留最近一次成功数据，并标记缓存/过期状态和通用刷新警告。

余额观测只显示总余额，不提供赠送或充值明细。存在正上限的余额显示 `remaining / cap`；无上限或上限非正的余额单独显示观测到的总额（保留两位小数），包括真实的 0 或负值。货币由行标签承载；缺失的金额保持未知并显示为破折号，不会伪造为零。
